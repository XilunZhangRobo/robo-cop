A robot should improve with experience.
Robo-COP learns from deployment to update both its policy
and the orchestrator that decides how to use it.

Overview

Improve the policy.
Rethink how to use it.

A robot orchestrator can work around a policy’s failures using scripted motion. But when the policy improves, the orchestrator needs to reconsider what it learned about that policy.

Robo-COP connects these updates. It curates skill demonstrations from deployment, including useful segments of failed trials, trains when warranted, and verifies candidates before adoption. It then revisits policy-dependent memory for the next deployment.

The harness

Method

The orchestrator is the language model that writes robot programs. The harness is the set of tools, task memory, and execution loop around it.

The agent can call the policy to pick up an object, or use perception to find a grasp and move the arm with scripted primitives. A visual monitor checks execution and sends feedback when revised code is needed.

Episode reflection updates task memory. Policy actions and scripted motions are recorded in a shared action stream. The curator extracts skill demonstrations from successful and failed episodes and checks them before adding them to the training data.

A controller decides when to train and names target skills for verification. Training uses all curated data accumulated so far. Verification checks task success, previously admitted skills, and whether the candidate itself performed its targets.

After adoption or reversion, advice that discourages VLA use is marked unverified for the policy now in service. Its history is kept, so the orchestrator can retest the skill rather than assume the old advice still applies.

Training data

A failed trial can still contain a useful grasp.

A text judge labels skills from code and execution feedback. A video judge checks the proposed labels. Segments are kept when the text judge accepts them and the video shows success or useful partial progress.

Held-out evaluation

Simulation results

After deployment, each system is tested on 50 new initializations per task with no further updates. Mean success is 73.8% for Robo-COP, 64.8% for the frozen-policy control, and 65.8% for fixed-schedule updates. ASPIRE reaches 54.0%; the standalone VLA reaches 28.0%.
